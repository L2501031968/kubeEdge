用户数据源

kb.json 
{
  "user_source": "/var/lib/kb/users.json",
  "ue_capacity": 64
}

user_source 指向 AMF / SMF / 设备模型导出的 JSON。推荐由导出器直接给出 online，也可以提供 registration_state、connection_state 和 session_state；不要让边缘控制台按 amari-ue-power 猜测用户在线。 示例： {"source": "...", "generated_at": "...", "capacity": 64, "users": [{"id": "ue-1", "online": true, "registration_state": "registered", "connection_state": "connected", "session_state": "active", "state": "connected", "sessions": 1, "bandwidth_mbps": 10, "prb_percent": 5, "rsrp_dbm": -85, "cell": "cell-1", "pod": "amari-ue-...", "node": "sdr"}]}。 云主机没有本地 user_source 时，会自动聚合已登记边缘控制台的 /api/users；当前目录存在 kb-users.json 时优先使用该文件。 没有配置、读取失败或边缘都不可达时，用户接入页显示「未接入用户数据源」，不会补零。

节点与网络标签

kubectl label node ... 
kb.local/name=d2000-edge          # 显示为 NTN-RAN
kb.local/name=sdr                 # 显示为 UE
kb.local/name=cloud               # 显示为 云端控制节点
kb.local/net-bandwidth-mbps=1000  # 网络资源池容量
nvidia.com/gpu=2                  # GPU / NPU / FPGA 等按扩展资源自动发现

只有集群真实上报的扩展资源才会出现在异构资源页；GPU / FPGA / NPU / DPU / ASIC 未上报时列在「未上报」提示里，不显示为 0。
